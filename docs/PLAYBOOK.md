# PLAYBOOK

专题操作规则。触及某个主题时打开对应小节，不要凭记忆补细节。

格式：**一句话规则。** 判据（怎样算做到了）。不写事故叙述。
规则总数有上限（`keel.toml` 的 `docs.playbook_max_rules`）：同一类规则合并；能写成检查的，写成检查后删掉对应的散文。

## 1. 证据与退出码

- **退出码是唯一的完成证据。** 判据：每条结论都对应一个直接读到的退出码；模型的陈述、日志里的 "passed"、「看起来对」都不算。
- **看门命令按退出码判断，不 grep 关键字。** 判据：不用自写的过滤模式判断成功；管道里用 `set -o pipefail`，或读 `${PIPESTATUS[0]}`。
- **匹配 0 个测试不是红，也不是绿。** 判据：过滤器实际选中的测试数被记录，并且等于预期。
- **编译错误、加载错误、夹具错误都不是行为上的红。** 判据：RED 的失败断言是本卡的契约断言，而不是 import、签名、初始化这类错误；夹具修正记为无效尝试。
- **会让进程提前退出的被测路径不能充当 RED。** 判据：断言之前不会出现 `exit` / `abort`；如有，就改成可观测的返回值。
- **不可逆的步骤以前一步的退出码为前提。** 判据：发布、推送、迁移用 `&&` 串起来，或显式检查退出码，不用 `;`。
- **多段命令要分别核对失败。** 判据：一批命令中任何一段缺文件或被截断，都要定点补读，不能拿最后一段的退出码代表整批。
- **测试汇总按执行器归属来算。** 判据：每个测试二进制或执行器的「选中数」都等于它自己的 pass/fail/ignore 之和，不跨执行器累加结果行。

## 2. 测试设计

- **一个测试证明一条契约，测试名是完整的句子。** 判据：失败时只看测试名，就知道违反了哪条契约。
- **边界值必跑 0、1 和上限。** 判据：每个有上限的测试都同时覆盖空、单个、恰好到上限、超过上限。
- **只断言「不超过 N」会放过在边界内丢内容的实现。** 判据：有界的测试同时断言内容完整，或者有明确的截断标记。
- **夹具的形状必须是真实系统会返回的形状。** 判据：夹具来自录制或对拍的样本，并注明来源；不按实现的方便来手捏。
- **状态闩要问「第二轮会怎样」。** 判据：一次性置位的标志位，有测试在循环的第二圈、重试和恢复之后检查它。
- **断言错误时把实际值写进失败信息。** 判据：失败输出能区分「目标上限被触发」和「提前超时」。
- **新的不变量配 property 测试或代码断言。** 判据：`docs/INVARIANTS.md` 有登记，而且「位置」一栏能解析到真实存在的代码。
- **property 测试固定种子，失败能复现。** 判据：失败输出里带种子和最小化后的反例。
- **制造失败却失败不了，这本身就是一个发现。** 判据：「出错时会怎样」类的测试，要先确认错误真的发生了，再断言后果。
- **复用组件时，验证真实的输入入口和异步调度。** 判据：测试从原始输入事件进入，并等待上游实际公开的状态变化，不凭接口名猜测行为。
- **只为测试存在的代码要显式标注。** 判据：测试专用的函数放在测试模块里，或者有生产调用点；不靠抑制「未使用」警告混过去。

## 3. 偶发用例

- **偶发判定要有协议，不刷重跑。** 判据：隔离单跑 ≥ 3 次全绿，并且全量重跑一次全绿，两者都写进卡；隔离也失败，就对照主线追根因。
- **不删用例，不放宽 deadline。** 判据：偶发修复的 diff 里，超时常量和断言都没有变松（`assert-guard` 会查）。
- **超时先定位卡在哪个阶段。** 判据：超时的报错能区分注册、执行、清理、加锁等阶段，不笼统地写 "timed out"。
- **整帧比较前关掉与契约无关的动效和时钟。** 判据：同一个快照测试连跑 10 次全绿。

## 4. 读取与路径

- **先拿到文件清单，再读文件。** 判据：作为参数的路径都来自当次 `rg --files`（隐藏目录加 `--hidden`）或 `git ls-files` 的清单；模块名、类型名不算路径证据。
- **发现路径和读取新路径分两次调用。** 判据：同一批命令里，不会先列目录、再读一个还没在清单里出现过的猜测文件名。
- **读取要有预算，截断就补读。** 判据：先看文件长度或 diff 的 hunk 列表，再按范围读；输出被截断后，只补读没返回的那一段。
- **跨仓库取证时，每个路径都绑定到它自己的仓库根。** 判据：同一条命令里有多个仓库时，所有路径都展开成绝对路径。
- **规划文档引用代码时写符号名，不写 `path:line`。** 判据：重构移动行号后，引用仍然有效。

## 5. 编辑与补丁

- **补丁按当前文件内容来定位。** 判据：匹配失败后先重读当前内容再重试，不把旧片段反复提交。
- **格式化之后再生成下一批补丁。** 判据：格式化命令确实已经结束，并且重读过它改写后的锚点。
- **同名字段要带上所属的结构体或作用域来定位。** 判据：补丁的锚点在文件里唯一。
- **共享配置字段要贯穿所有构造点。** 判据：扩展配置后，一次检索出所有字面量构造点，再开始编译。
- **故障注入之后要让构建缓存失效。** 判据：恢复源码后，受影响的编译单元确实重新编译过（优先用 `keel-inject`，它在临时 worktree 里执行，并且不和工作树共享缓存）。
- **非交互地覆盖或删除文件时，要绕过 shell 别名。** 判据：用 `command cp -f` / `command rm -f`（`cp -i` / `rm -i` 别名在无输入时默认答 n，覆盖被静默跳过），或 `git checkout -- <path>`（仅当没有其他未提交改动时）；之后用 `cmp` 或 `grep` 确认结果。

## 6. 并行与归属

- **并行卡的文件归属按目录来划。** 判据：同一时间每个目录最多只有一张卡在改；卡里列的文件只当阅读提示，不当边界。
- **依赖的决策必须已经提交。** 判据：后续任务只在它依赖的决策或卡已经 commit 之后才派发，不能只停留在工作区。
- **不要在子任务正在工作的分支上写东西。** 判据：委托出去之后，那个分支或 worktree 归它；合并由父任务完成。
- **工作区里冒出来的文件不一定是你写的。** 判据：用 `git log -1 --format='%an%n%b' -- <path>` 判断归属；不暂存别人的改动。
- **分支合入前，先在最新的主线上编译。** 判据：主线如果改过契约版本，先把主线合进分支，跑完 gate 再合入。

## 7. 环境与进程

- **测试不得重启或杀掉作者正在用的常驻进程。** 判据：测试用私有的 socket、端口、数据目录；只结束本会话自己启动的进程。
- **隔离的验证副本使用独立的构建目录。** 判据：临时 worktree 的构建产物不写进主工作区（keel 默认用 `.keel/cache/`）。
- **新进程「返回」不等于已经就绪。** 判据：等它给出明确的就绪信号（握手、prompt、健康检查）后再交互。
- **假设出来的参数要标注为假设，并给出测量脚本。** 判据：每个常量的注释都写明它是「实测」还是「假设」；假设的附测量方法。
- **证据用锁定版本的工具产生。** 判据：测试与检查命令直接调用 `node_modules/.bin/<工具>` 这类锁定的本地二进制，不经 `npx` / `bunx` / `pnpm exec`——它们缺依赖时会静默临时安装另一个版本；缺依赖时命令失败，而不是换个版本继续。
- **共享构建缓存会把故障注入的产物带给工作树。** 判据：验证用的私有缓存只给临时 worktree 用；工作树的绿灯用它自己的构建目录（keel 默认如此）。构建工具按修改时间判断是否重编，新检出的源码可能比缓存里的产物更旧。

## 8. 秘密与脱敏

- **新增落盘字段先过脱敏边界。** 判据：用一个形状逼真的假 key 当金丝雀，分别放进用户输入、工具输出、命令参数里跑一遍；所有落盘的字节中都找不到它，执行时又确实拿到了真值。
- **日志统一走脱敏层。** 判据：没有绕过统一 logger 直接打印的地方；新出现的敏感字段名加进脱敏表。
- **认不出来的路由和权限默认拒绝。** 判据：新增的接口如果没有分类，结果是 403，而不是放行。

## 9. 文档与决策

- **决策编号唯一，并且递增。** 判据：`check-docs` 通过；新决策只修订旧决策的某一条时，在旧条文原处加一个指向新决策的指针。
- **调研要带证据。** 判据：调研笔记写明来源链接、检索日期、项目 star 数和许可证；结论和证据分开写。
- **一条规则被正确执行却产生了坏结果，要改的是类型或检查，不是规则的措辞。** 判据：修复让这种坏结果在类型层面或检查层面无法表达。
- **写文档用的 heredoc 要给结束标记加引号。** 判据：`<<'EOF'`，避免反引号和 `$` 被 shell 展开。

## 10. 发布

- **发布以作者当次的明确授权为前提。** 判据：没有授权时，发布入口只做预检。
- **攒批发版。** 判据：只有无法安装或启动、数据丢失、安全问题这几类才走热修；普通修复进下一批。
- **发布证据是可复验的。** 判据：版本记录里写明构建的 commit、产物校验和，以及验证命令和它们的退出码。
